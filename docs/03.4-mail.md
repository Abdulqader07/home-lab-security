# Mail Service

**Role:** SMTP (send) and IMAP/POP3 (read) for lab.local.
**Host:** Mail Server (192.168.20.3)
**Software:** Postfix, Dovecot
**FQDN:** mail.lab.local

## Architecture
```Sender -> SMTP -> Postfix -> LDAP lookup -> Maildir
Client -> IMAP -> Dovecot -> LDAP bind```


## DNS Records

| Name | Type | Value |
|---|---|---|
| mail.lab.local | A | 192.168.20.3 |
| lab.local | MX | 10 mail.lab.local. |

## How It Works

1. Postfix receives mail for lab.local
2. Queries LDAP to confirm recipient exists
3. LDAP returns mailbox path (homeDirectory)
4. Postfix delivers to /home/USER/Maildir/
5. Dovecot authenticates IMAP clients via LDAP

## LDAP Integration

| Account | Used by |
|---|---|
| cn=postfix,ou=services | Postfix mailbox lookup |
| cn=dovecot,ou=services | Dovecot authentication |

## Mailbox Layout

Each user has a Maildir with cur/, new/, tmp/.
Messages move from new/ to cur/ once read.

## Ports

| Port | Service |
|---|---|
| 25 | SMTP |
| 587 | Submission |
| 143 / 993 | IMAP / IMAPS |
| 110 / 995 | POP3 / POP3S |

## Verification

```postmap -q "ali@lab.local" ldap:/etc/postfix/ldap-mailbox.cf
doveadm auth test sara PASSWORD
nc mail.lab.local 143```


## Gotchas

- Rocky 10 dropped Berkeley DB - Postfix maps must use lmdb:, not hash:
- Dovecot 2.4 rewrote LDAP config - old 2.3 tutorials don't apply
- Debian Postfix needs compatibility_level = 3.6 and explicit
  smtpd_relay_restrictions with reject_unauth_destination
- Missing /etc/aliases causes fatal errors - run newaliases
- Bad network values like 192.168.20./24 silently break mynetworks
- Group/world-writable config files are refused by Postfix
- mail_driver and mail_path must be top-level in Dovecot config

## Not Implemented

- TLS
- Spam filtering
- DKIM / SPF
- Virtual users
- Public internet exposure
