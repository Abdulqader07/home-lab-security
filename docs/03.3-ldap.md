# LDAP Directory (389 Directory Server)

**Role:** Central identity store.
**Host:** Rocky Linux Server (192.168.20.2)
**Software:** 389 Directory Server
**Ports:** 389 (LDAP), 636 (LDAPS)

## Why LDAP

One central place where all users live. Mail, SSH, web apps query
LDAP instead of keeping their own user lists.

## Why 389 DS

Red Hat's LDAP server, shipped in the RHEL/Rocky ecosystem.
Replaces OpenLDAP, which Red Hat deprecated. Uses MDB backend.

## Installation

| Command | Purpose |
|---|---|
| dnf install 389-ds-base | install server |
| dscreate interactive | create instance |

## Object classes for users

| objectClass | Provides |
|---|---|
| top | required for all entries |
| person | requires cn, sn |
| organizationalPerson | org fields |
| inetOrgPerson | mail, uid |
| posixAccount | uidNumber, gidNumber, homeDirectory, loginShell |

## ACIs

Attached to ou=people,dc=lab,dc=local:

| Rule | Grants | To |
|---|---|---|
| postfix-read-people | read, search on mail/uid/cn/sn | cn=postfix,ou=services |
| dovecot-read-people | read, search on all attributes | cn=dovecot,ou=services |

Least privilege: each service account gets only what it needs.

## ACI vs IAM

ACIs are LDAP's IAM - principal, action, resource.

| IAM (AWS) | ACI (LDAP) |
|---|---|
| IAM role | Bind DN |
| s3:GetObject | read, search |
| S3 bucket ARN | Target OU |
| Policy document | aci: attribute |

## LDAP vs Active Directory

| | LDAP | AD |
|---|---|---|
| Protocol | LDAP | LDAP + Kerberos |
| Auth | Simple bind | Kerberos |
| DNS | Separate | Built in |
| Group Policy | No | Yes |
| Cross-platform | Any OS | Windows-first |
| Cost | Free | Windows Server license |
| Management | CLI/GUI | GUI-first |

AD is Microsoft's LDAP bundled with Kerberos, DNS, and GPO.

## Gotchas

- Rocky 10 doesn't ship OpenLDAP server - use 389 DS
- ACIs are attributes on the OU, not separate entries
- The wizard creates lowercase OUs (ou=people, not ou=People)
